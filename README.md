# Pickleball Club

TypeScript + Three.js + Vite로 만드는 가벼운 3D 피클볼 게임입니다.
현재 **5단계: 사운드·애니메이션·조작감 개선**까지 구현되어 있습니다.

## Windows에서 실행하기

1. [Node.js 공식 사이트](https://nodejs.org/)에서 **LTS 버전(22.12 이상, 권장 24)**을 설치합니다.
2. 이 저장소를 다운로드하고 압축을 풉니다.
3. `package.json`이 있는 폴더를 열고, 탐색기 주소창에 `cmd`를 입력한 뒤 Enter를 누릅니다.
4. 처음 한 번 아래 명령을 입력합니다.

   ```bat
   npm ci
   ```

5. 실행할 때마다 아래 명령을 입력합니다.

   ```bat
   npm run dev
   ```

6. 명령 창에 표시되는 `Local` 주소를 Chrome 또는 Edge에서 엽니다. 보통 `http://localhost:5173`입니다.
7. 종료하려면 명령 창에서 `Ctrl+C`를 누릅니다.

`index.html` 파일을 직접 더블클릭하지 말고 위 방법으로 실행하세요. 패키지 설치에는 인터넷이 필요하지만 게임은 유료 서비스나 외부 API를 사용하지 않습니다.

## 현재 가능한 기능

- 실제 비율의 코트(20 × 44피트), 키친, 네트와 라인
- 파란 스포츠 셔츠의 3등신 SD 시험용 플레이어와 빨간 스포츠 셔츠의 기존 인체 비율 CPU
- 모델링된 얼굴·머리카락·목·손과 손가락, 자연스러운 인체 비율의 반팔·반바지·양말·운동화
- 선수별 복장·피부·머리카락 재질과 손목에 부착된 패들 면·그립
- 팔꿈치·무릎·발목 관절을 사용한 걷기와 몸통 회전·팔 스윙. 경기 판정은 캐릭터 루트 위치를 기준으로 기존대로 유지
- 플레이어는 자체 제작 SD GLB, CPU는 Quaternius의 CC0 인체 GLB를 사용합니다. 모델별로 뼈대와 스윙 클립을 분리합니다.
- **W / A / S / D**: 앞 / 왼쪽 / 뒤 / 오른쪽으로 이동 (한글 입력 상태에서도 물리 키 기준)
- 대각선 이동 속도 보정, 빠르게 가속·감속하는 부드러운 이동
- 드라이브·딩크에 맞춘 팔 스윙과 몸 회전, 이동 시 기울임과 자연스러운 대기 동작
- 플레이어를 부드럽게 따라가는 3인칭 카메라
- 내 코트와 주변 여유 공간 안에서 이동, 네트 통과 제한
- 마우스 이동: 상대 코트의 노란 원으로 목표 지점 지정 (라인 밖도 조준 가능)
- **왼쪽 클릭**: 빠르고 낮은 드라이브 / **오른쪽 클릭**: 부드럽게 띄우는 딩크
- 딩크는 상대 키친 가까이에 직접 조준하세요. 네트 가까이에서 더 정확합니다.
- 공 가까이 접근하면 작은 이동 보조가 작동하지만 **자동 타격은 하지 않습니다.**
- 공이 너무 멀거나 너무 낮거나 높으면 헛스윙합니다. 화면의 초록색 타격 가능 안내를 참고하세요.
- 밝은 노란 공과 짙은 남색 윤곽선, 약 두 배 커진 기본 표시 크기와 원거리 가독성 보정
- 공 아래의 진한 그림자와 밝은 테두리, 대비를 강화한 예상 착지 원
- 오른쪽 위 **게임 속도**: **0.5배 / 0.75배(기본·권장) / 1배(기존 속도)**. 선택은 브라우저에 기억
- 속도 변경은 즉시 공·선수 이동·CPU 반응과 이동·타격 간격·경기 대기 시간에 함께 적용됩니다. 포물선과 경기 규칙은 유지됩니다.
- 중력, 감속 바운드, 네트 충돌, 아웃과 두 번 바운드 안내
- 보통 난이도 CPU: 공의 예상 바운드 이후 위치를 계산해 이동하고 타격
- 약 0.22~0.38초 반응 지연, 제한된 이동 속도와 타격 범위
- 네트 가까이에서 딩크, 후방에서 드라이브 선택. 가끔 빈 공간 공격
- 어려운 공은 헛스윙하거나 조준이 흔들리며, 타격 후 수비 위치로 복귀
- 점수판: **11점 이상 + 2점 차**로 승리. 서브권을 가진 선수만 득점
- 리시버가 랠리를 이기면 점수 없이 서브권 이동
- 서버 점수가 짝수면 오른쪽, 홀수면 왼쪽에서 대각선 서브
- 서브 착지는 키친·키친 라인을 제외한 올바른 서비스 코트에 해야 함
- **투바운스 룰**: 서브는 리시버 쪽에서, 첫 리턴은 서버 쪽에서 각각 바운드한 뒤 타격. 이후 발리 허용
- 키친 내부와 경계선에서 발리 금지. 키친 안에서 바운드한 공을 치는 것은 허용
- 발리 후 전진하며 키친에 들어가는 관성 반칙 검사, 득점 확정 전 판정 반영
- 사이드라인·베이스라인 착지는 인, 선 밖은 아웃. 두 번째 바운드는 리시버 폴트
- 네트·서브 발 위치·대각선 서비스 코트 폴트와 안내 메시지
- **랠리 횟수**: 서브부터 이어진 타격 횟수 (경기 점수와 다름)
- **새 경기** 버튼: 점수·서브권·두 선수 위치 초기화
- 득점·서브권 변경은 화면 중앙에 크게 약 2초간 표시하고 마지막 0.35초 동안 페이드아웃
- 플레이어 득점: `POINT! - 플레이어 득점` / CPU 득점: `CPU SCORES! - CPU 득점`
- 점수 없는 서브권 변경: `YOUR SERVE!` / `CPU SERVE!`
- 알림이 완전히 끝난 뒤 다음 서브를 준비. 속도 설정과 무관한 실제 시간 기준이며, 일시정지·탭 이동 중에는 알림 시간도 정지
- 경기 종료 시 `YOU WIN!` / `YOU LOSE!` 중앙 알림과 다시 경기하기. 상단 점수판은 계속 표시
- 드라이브·딩크·서브·바운드·네트·헛스윙·폴트·득점·서브권 변경·승패에 맞춘 효과음
- 오른쪽 위 **소리 켜짐/꺼짐**, **소리·화면 설정** 안의 음량 조절 (브라우저에 기억)
- **P / Esc** 또는 **일시정지** 버튼: 경기 멈춤/재개. 다른 창이나 탭으로 이동하면 자동 정지
- 예상 첫 바운드 위치 표시 (하늘색 원, 아웃 예상은 주황색), 타격 가능 거리 표시
- 좋은 타점·낮은 공·높은 공·먼 공 안내, 드라이브/딩크 타격 피드백
- 공의 짧은 궤적과 바운드·타격 파장, 득점 강조 효과
- **화면 효과 줄이기**: 궤적·파장·미세한 들썩임을 줄임. 운영체제의 모션 감소 설정을 기본으로 따르고 선택을 기억

## 처음 플레이하기

웹 배포가 완료되면 [게임 열기](https://klvrandol.github.io/pickleball-game/)를 누르세요.

1. 기본 속도는 **0.75배**입니다. 더 여유가 필요하면 오른쪽 위에서 **0.5배**, 이전 속도는 **1배**를 선택하세요. **경기 시작**을 누릅니다. 첫 서브는 플레이어입니다.
2. 처음 배치된 위치에서 **Space** 또는 **서브 공 떨어뜨리기**를 누릅니다.
3. 떨어진 공이 땅에 튀면 **왼쪽 클릭**으로 칩니다. 초록색 타격 가능 안내를 참고하세요.
4. 노란색으로 칠해진 대각선 서비스 코트를 마우스로 조준하세요. 마우스를 움직이지 않으면 기본 목표는 올바른 서비스 코트입니다.
5. 서브 후 W로 조금 전진해 다음 공을 준비하세요. CPU의 첫 리턴도 내 코트에서 바운드한 뒤 쳐야 합니다.
6. 이후 W/A/S/D로 이동하고 왼쪽 드라이브·오른쪽 딩크를 직접 클릭해 경기를 이어갑니다.
7. 공을 놓치면 점수·서브권 처리 후 다음 서브 위치로 두 선수를 자동 배치합니다. CPU 서브는 자동 진행됩니다.

소리는 **경기 시작 같은 직접 클릭 후** 재생됩니다. 오른쪽 위 버튼으로 언제든 음소거할 수 있고, 왼쪽 **소리·화면 설정**에서 크기를 바꿀 수 있습니다. 효과음은 브라우저에서 직접 합성하므로 외부 음원·다운로드·유료 서비스가 없습니다. 소리를 사용할 수 없는 환경에서도 게임은 동작합니다.

일시정지 후에는 **계속 플레이** 또는 P / Esc로 재개하세요. 창을 벗어나 자동 정지된 경우에도 직접 재개해야 합니다. 멈춘 동안 공과 CPU, 점수와 다음 서브 대기 시간이 모두 정지합니다.

하늘색 원은 현재 공의 속도와 중력으로 예측한 첫 바운드 위치입니다. 네트 접촉 이전의 예상이며 실제 착지·충돌 판정은 따로 이루어집니다. 초록색 타격 가능 표시와 함께 **좋은 타점** 안내를 참고하고, 낮은 공은 딩크를 사용해보세요.

서브 공을 놓쳤다면 Space로 다시 떨어뜨릴 수 있습니다. 서브 전에 선을 밟거나 다른 좌우 구역으로 이동하면 서브 발 반칙이 됩니다.

## 규칙 구현 범위와 단순화

공식 단식의 사이드아웃 점수 방식, 서브 좌우·대각선 착지, 투바운스 룰과 주요 키친 반칙을 구현했습니다. 이번 버전은 다음 부분을 단순화했습니다.

- **드롭 서브만 사용**합니다. 공을 밀어 던지지 않고 수직으로 떨어뜨려 바운드 후 타격합니다. 일반 발리 서브는 구현하지 않았습니다.
- 공의 착지 중심과 선 두께로 인/아웃을 계산하고, 선수 발은 작은 사각형 영역으로 판정합니다. 실제 공·발의 변형까지 계산하지는 않습니다.
- 발리 후 관성은 최소 **0.6초**, 그 이후에도 계속 네트 쪽으로 전진 중이면 멈추거나 뒤로 움직일 때까지 검사합니다. 이 기간의 키친 진입은 공이 이미 멈췄어도 폴트로 반영하며, 점수 확정을 잠시 미룹니다. 실제 신체 균형과 발걸음 전체를 재현한 판정은 아닙니다.
- 점프 버튼은 없습니다. 실제 조작 캐릭터는 지상에서 움직입니다. 규칙 엔진은 공중 상태가 전달되면 키친에서의 이륙과 착지를 추적하며, 키친에서 벗어나 양발이 다시 지면에 닿기 전 발리는 금지합니다.
- 네트 충돌은 즉시 폴트 처리합니다. 네트 테이프를 맞고 넘어가는 유효한 공과 서브는 재현하지 않습니다.
- 서브 10초 제한, 코트 엔드 교대, 타임아웃, 신체·복장·라켓의 우발적인 접촉 판정은 생략했습니다.
- 플레이어가 첫 서버로 고정됩니다. CPU도 4구부터 발리를 시도하며, 반응 지연과 실수 확률이 적용됩니다.


공은 시인성을 위해 표시만 크게 하고, 거리가 멀어지면 화면에서 너무 작아지지 않도록 보정합니다. 실제 충돌 반지름과 인/아웃 판정은 기존대로 유지합니다. 헛스윙 후에는 게임 시간 0.3초 뒤 다시 칠 수 있습니다(실제 시간은 0.75배에서 0.4초, 0.5배에서 0.6초). 불안정한 자세에서는 조준 오차가 생겨 네트나 아웃이 발생할 수 있습니다.

## 빌드 확인

```bat
npm test
npm run build
npm run preview
```

`build`는 TypeScript 오류 검사 후 배포 파일을 `dist` 폴더에 만듭니다. `preview`는 만든 결과를 확인하는 서버입니다.

## 파일 구성

- `src/main.ts`: 3D 코트와 캐릭터 연결, 이동, 카메라
- `src/athlete.ts`: 스키닝 인체 모델, 손목 패들, 원본 이동 애니메이션과 타격 IK
- `src/athlete-model.ts`: GLB 로딩·검증과 스켈레톤 복제
- `src/ball.ts`: 포물선 타격 계산, 중력·바운드·충돌
- `src/cpu.ts`: CPU의 예측 이동, 반응 지연, 타격 판단
- `src/match.ts`: 점수, 서브권, 서브 착지, 투바운스·키친 판정과 확정된 랠리 결과
- `src/result-notice.ts`: 결과별 중앙 문구, 실제 시간 2초 표시·페이드와 다음 서브 대기
- `src/audio.ts`: 외부 파일 없는 효과음 합성과 음량·음소거 설정
- `src/feedback.ts`: 예상 바운드와 타점 안내 계산
- `tests/`: 공·CPU·경기 규칙과 실제 서브 궤적 검사
- `src/style.css`: 안내 화면 디자인
- `index.html`: 화면과 조작 안내

## 개발 진행 상태

기본 기획의 1~5단계를 구현했습니다. 이후에는 실제 플레이 피드백에 맞춰 난이도와 타격감을 조정하고, 위에 명시한 규칙 단순화 항목을 개선할 수 있습니다.

## 발리 조작과 구현

- **서브(1구) → 바운드 후 리턴(2구) → 바운드 후 타격(3구) → 4구부터 발리** 순서입니다.
- 버튼은 그대로입니다. 왼쪽 클릭은 빠른 발리, 오른쪽 클릭은 부드러운 발리입니다. 마우스로 착지 지점을 조준합니다.
- 공이 공중에 있어도 패들이 닿는 범위와 높이에서만 타격됩니다. 클릭 후 약 0.065 게임 초의 스윙 준비를 거치며, 공이 그 사이 멀어지면 헛스윙합니다. 자동 타격은 없습니다.
- 실제 접촉 높이에서 궤적을 계산합니다. 빠른 공은 블록, 느리고 높은 공은 공격, 오른쪽 클릭은 짧고 부드러운 궤적을 사용합니다. 낮은 접촉은 네트에 걸릴 수 있습니다.
- CPU는 키친 밖에서 발리를 준비하고, 빠른 공에 블록·높은 공에 공격·네트 근처에 부드러운 발리를 사용합니다. 어려운 공은 놓칠 수 있습니다.
- `src/volley.ts`: 타격 범위, 스윙 접촉 시간과 발리 궤적
- `src/cpu.ts`, `src/main.ts`: CPU 판단과 기존 조작 연결
- `src/athlete.ts`: 접촉 높이에 맞춘 어깨·팔꿈치·패들 동작
- `src/match.ts`: 이륙·착지 상태와 키친 후속 반칙 판정
- `tests/volley.test.ts`: 투바운스, 발리·키친·CPU·점수 및 패들 접촉 검증

## 상황별 스윙 애니메이션

포핸드/백핸드는 선수의 몸 방향을 기준으로 공의 좌우 위치를 계산하여 선택합니다. CPU는 반대편을 바라보기 때문에 같은 월드 좌표의 공도 반대 손 방향으로 판정될 수 있습니다. 두 선수 모두 오른손 패들을 유지합니다.

- 드라이브: 큰 준비 회전과 빠른 임팩트, 몸을 가로지르는 높은 마무리
- 딩크: 작은 준비 동작과 부드럽게 밀어 올리는 짧은 마무리
- 발리: 짧은 준비와 빠른 블록, 작은 전방 마무리. 오른쪽 클릭의 부드러운 발리도 이 기본 자세를 사용하며 공의 속도·궤적은 기존 타격 시스템이 구분합니다.
- 백핸드: 몸 반대편에서 패들을 모으고 팔꿈치 방향 및 보조 팔 자세를 변경합니다.
- CPU는 동일한 시스템을 사용하며 회전과 마무리 크기를 약간 줄여 구분합니다. 공 접촉 위치와 시간은 동일합니다.

`src/swing.ts`가 타격 종류·손 방향·준비/임팩트/회복 시간을 관리하고, `src/athlete.ts`가 관절과 패들을 움직입니다. `src/main.ts`와 `src/cpu.ts`에서 실제 타격에 연결합니다. 애니메이션 때문에 공의 속도, 타격 판정, CPU 반응 지연이나 규칙을 바꾸지는 않습니다. 이제 로컬 GLB의 스키닝 모델·이동 애니메이션을 사용하며, 추가 패키지나 실행 중 외부 에셋 서비스는 사용하지 않습니다.

`tests/swing.test.ts`는 여섯 가지 조합의 실제 패들·몸통 자세 차이, 임팩트 오차, 선수 방향에 따른 손 선택, CPU 변형, 회복과 초기화를 확인합니다.

## 전신 키프레임 스윙과 개발용 테스트 화면

[스윙 테스트 화면 열기](animation-test.html) — 로컬에서는 개발 서버 주소 뒤에 `/animation-test.html`을 붙이면 됩니다. GitHub Pages에도 동일한 파일을 배포합니다. 게임 화면과 별도로 실행되며 점수나 경기 상태를 조작하지 않습니다.

1. 동작에서 포핸드/백핸드 드라이브·딩크·발리 중 하나를 고릅니다.
2. 선수(파란 플레이어/빨간 CPU)를 선택하고 반복 재생하거나 재생 속도를 0.25/0.5/1배로 조절합니다.
3. 동작 위치 슬라이더로 준비→임팩트→마무리를 살펴봅니다. **50%가 임팩트**이며 ‘임팩트 보기’를 누르면 해당 위치에 멈춥니다.
4. 공 높이와 타격 방향을 바꿔 자세 보정을 확인합니다. 노란 공은 접촉 목표이고 임팩트 안내에 접촉 오차가 표시됩니다.
5. 화면을 드래그하면 시점이 회전하고 휠로 확대/축소합니다.

### 여섯 동작의 차이

| 동작 | 준비 | 임팩트·마무리 |
|---|---|---|
| 포핸드 드라이브 | 오른쪽 뒤로 패들을 빼고 뒷발에 체중 싣기 | 골반→척추→어깨 순서로 풀며 몸 반대편 위로 마무리 |
| 백핸드 드라이브 | 패들을 왼쪽 몸 앞에 모으고 반대 방향으로 몸통 감기 | 반대 방향 회전, 오른쪽 앞으로 펼쳐지는 마무리 |
| 포핸드 딩크 | 무릎을 낮추고 오른쪽 아래에 작은 준비 | 몸통 회전을 줄이고 패들을 짧게 위로 밀기 |
| 백핸드 딩크 | 무릎을 낮추고 왼쪽 몸 앞에 패들 모으기 | 팔꿈치를 몸 가까이 두고 왼쪽 앞에서 부드럽게 들어 올리기 |
| 포핸드 발리 | 오른쪽 앞에서 패들을 세우고 상체 고정 | 작은 전방 블록, 빠른 준비 자세 복귀 |
| 백핸드 발리 | 몸 앞을 가로질러 왼쪽 앞에 패들 준비 | 손목을 안정시키고 왼쪽 앞에서 짧게 막기 |

### 구현 순서와 유지한 동작

- `src/swing-keyframes.ts`: 모션별로 직접 설계한 시간·패들·골반/척추/어깨·손목·무릎 하중·체중 이동·보조 팔 포즈. 모션 캡처 데이터는 아닙니다.
- `src/athlete.ts`: 원본 뼈대에 포즈를 맞춰 여섯 **Three.js AnimationClip**으로 한 번 변환합니다. 각 클립은 31개 뼈의 회전/위치 트랙과 61개 시간 샘플을 가지며, 선수 사이에서 클립을 공유합니다. 원본 `athlete.glb`·스켈레톤·스키닝은 변경하지 않았습니다.
- 적용 순서: **원본 대기/이동 클립 → 전신 키프레임 혼합 → 공 높이·방향 보정 → 발 고정/무릎 보정 → 임팩트 주변 팔 IK → 스키닝 업데이트**. IK는 준비와 마무리를 만드는 데 사용하지 않고 임팩트 근처에서만 접촉을 보정합니다. 클립 제작 때의 팔/다리 위치 계산은 로딩 시 한 번만 수행합니다.
- 골반과 몸통의 회전 시점을 어긋나게 하고 손목과 보조 팔도 별도 키프레임으로 움직입니다. 정지 타격은 발의 수평 좌표를 유지하며 뒷발을 조금 들어 하중 변화를 표현합니다. 이동 타격은 보행의 발 목표를 사용해 기존 이동을 이어갑니다.
- `src/swing.ts`: 애니메이션 시간만 관리합니다. 기존 **0.065 게임 초의 클릭 후 접촉 지연**, 즉시 처리하던 CPU 바운드 타격과 서브, 공 물리·조작·AI 판단·점수·규칙은 유지합니다. 접근 중 예비 자세로 연결하고, 이미 접촉한 타격은 임팩트부터 재생합니다. 테스트 화면은 준비를 관찰하기 위해 실제 경기보다 긴 준비 시간을 사용합니다.
- `src/animation-test.ts`, `src/animation-test.css`, `animation-test.html`: 독립된 개발용 확인 화면. `vite.config.ts`는 게임과 테스트 화면을 함께 빌드합니다.
- `tests/swing-keyframes.test.ts`: 실제 클립 트랙, 회전 순서, 여섯 스윙×두 선수×세 높이의 접촉, 발 고정, 이동 유지, 반복·정지 프레임의 안정성을 검증합니다.

## SD 플레이어 시험 적용 / 기존 스타일 비교

이전 시험 옵션 `?player=sd`는 **플레이어만 SD**, CPU는 기존 인체 비율입니다. 코트·카메라·WASD·위치 보정·공 물리·타격 범위·AI·점수·규칙·중앙 알림은 그대로입니다.

- [SD 플레이어로 게임 실행](./?player=sd)
- [기존 인체 비율 플레이어로 비교](./?player=classic)
- [스윙 비교 화면](animation-test.html): ‘플레이어 스타일’에서 SD/기존을 선택합니다. CPU를 고르면 기존 스타일을 유지합니다.

SD 모델은 기존 모델의 머리만 키운 것이 아닙니다. 빈 장면에서 넓은 얼굴과 머리, 작은 몸통, 짧고 통통한 팔·다리, 반바지·넓은 운동화·파란 모자를 새로 모델링했습니다. 전체 높이는 기존 코트와 카메라에 맞춰 비슷하게 유지하며 머리 높이가 전체의 약 1/3입니다. 짧은 다리의 경쾌한 이동 클립, 굽힌 준비 자세, 앞에 든 패들, 18% 큰 패들을 사용합니다.

- `tools/build-sd-athlete.py` → `assets/athlete-sd.glb`: 자체 제작 모델/29관절 리그/기초 이동 클립. 실행 중 Blender나 외부 에셋 서비스는 사용하지 않습니다.
- `src/athlete-model.ts`: SD와 기존 모델을 별도로 로딩·검증·복제합니다.
- `src/athlete.ts`: 모델에 맞춰 별도로 스윙 클립을 굽고, SD의 회전 동작을 조금 과장합니다. 짧은 팔과 큰 패들에 맞춘 손목·상체 보정은 시각 표현만 바꾸며 공 접촉 높이·타격 범위·타격 성공/실패 판정은 변경하지 않습니다.
- `src/main.ts`: 기본 SD 플레이어와 `?player=classic` 비교 옵션. CPU 생성 방식은 기존 스타일입니다.
- `animation-test.html`, `src/animation-test.ts`: 플레이어 스타일 A/B 선택.
- `tests/sd-athlete.test.ts`: 약 3등신 비율, 실제 팔·다리 길이 감소, CPU 유지, 모델별 클립 분리와 준비 자세 검증. 기존 타격·규칙 테스트도 SD 플레이어로 실행합니다.

### 이번 시험 버전의 한계

SD의 짧은 팔로 기존 타격 범위를 유지하기 위해 가까운 공에서는 손목 접힘, 먼/높은 공에서는 작은 상체 뻗기 보정이 들어갑니다. 극단적인 공 위치에서는 자세가 과장되거나 큰 머리와 패들이 겹칠 수 있습니다. 피부 변형과 손가락 표현은 단순하며 모델링·애니메이션의 최종 완성본은 아닙니다. 커진 신발과 패들의 외형이 경기의 발 판정·타격 범위를 넓히지는 않습니다.

CPU의 SD 전환은 별도 후속 작업으로 남겼습니다. 현재 버전으로 코트 시인성, 공·머리·패들 겹침과 조작감을 먼저 비교한 뒤 같은 스타일로 통일하는 것이 좋습니다.


## KayKit Ranger 플레이어 시험 적용

현재 기본 플레이어는 업로드된 KayKit Adventurers Ranger이며 CPU는 기존 Quaternius `athlete.glb`입니다. 원본 모델과 SD 구현은 삭제하지 않았습니다.

- 기본 `./` 또는 `?player=ranger`: Ranger
- `?player=classic`: 기존 Quaternius 플레이어 비교
- `?player=sd`: 앞서 만든 SD 플레이어 비교
- `animation-test.html`: Ranger/SD/기존 모델 선택, 여섯 스윙 반복·임팩트 확인

`Ranger.glb`를 그대로 `public/models/Ranger.glb`에 복사했습니다. 실제 모델은 23개 관절과 스키닝이 있지만 애니메이션 클립이 없습니다. `src/ranger.ts`가 원래 뼈대에 맞게 오른손 패들, 약 1.8m 높이, 발바닥 높이와 앞 방향을 조절합니다. Quaternius의 관절 회전 트랙을 강제로 재생하지 않습니다. 기존 스윙의 시간/패들 이동 경로만 공유하고, Ranger의 실제 손·손목·팔꿈치·어깨 체인을 별도 IK로 움직입니다. 공과 패들 접촉 시점, 타격 범위, 물리·점수·AI·카메라는 변경하지 않았습니다.

한계: 현재 이동과 여섯 스윙은 외형 확인용 동작입니다. 초기 시험 버전에서는 망토·화살통을 유지했지만, 아래 스포츠 의상 버전에서는 제거했습니다. 가까운 백핸드/높은 공에서는 손목이 과하게 꺾이거나 머리·패들과 겹칠 수 있고, 이동 시 발 미끄러짐이 남을 수 있습니다. 자연스러운 후속 버전에는 KayKit 뼈대 전용 이동·스윙 클립 또는 별도 리타기팅과 관절 제한이 필요합니다.

검증: `npm test`(74개), `npm run build`, Chromium의 텍스처 로딩·6스윙 임팩트·이동·드라이브/딩크/발리·규칙 확인. Node 리그 테스트만 이미지 디코더가 없어 텍스처 참조를 제외하며, 브라우저는 원본 GLB 전체를 로딩합니다.


## Ranger 크기·가독성 보정

Ranger의 표시 모델과 패들은 이전 크기의 65%입니다(기준 몸높이 약 1.17m). 발바닥의 코트 높이는 유지하고, 게임용 선수 루트는 배율 1로 유지합니다. 이동 속도·타격 범위·공 크기/물리·AI·경기 규칙은 그대로입니다. 작은 팔로 기존 범위의 높은 공을 칠 때는 시각 전용 팔 IK 길이와 작은 상체 뻗기를 보정합니다. 극단적인 높은 공에서는 팔이 과장되어 보일 수 있습니다.

Ranger 사용 시에만 카메라 높이를 10.8→11.4, 기본 뒤쪽 거리를 15.5→15.9로 조금 늘렸습니다. 추적 비율과 부드러운 이동 방식은 유지합니다. 공에는 비어 있는 이중 테두리를 추가해 머리·몸 뒤에서도 위치를 볼 수 있습니다. 테두리는 화면 표시만 바꾸며, 기존 공과 바닥 그림자·착지 표시는 유지합니다.

변경: `src/ranger.ts`, `src/main.ts`, `src/ball-locator.ts`, `tests/ranger.test.ts`, `tests/ball-locator.test.ts`. 검증: 75개 테스트, 빌드, 실제 머리 뒤 공의 테두리 표시·축소 비율·발 높이·타격 동작 브라우저 검사.


## Ranger 스포츠 의상 버전

기본 플레이어는 원래 얼굴·헤어스타일·머리 크기·체형을 유지한 스포츠 복장 Ranger입니다. CPU, 65% 표시 크기, 카메라, 공 윤곽선, 이동·타격·경기 규칙은 그대로입니다.

- 원본 `Ranger.glb`와 `public/models/Ranger.glb`는 변경하지 않았습니다. 런타임은 별도 `public/models/Ranger-sports.glb`를 사용합니다.
- 망토와 화살통은 별도 메시라 제거했습니다. 몸통에는 스카프·벨트·주머니가 함께 들어 있어 해당 의상 표면을 새 스포츠 셔츠와 반바지로 재구성했습니다. 가죽 팔 보호구와 긴 부츠 부분도 제거했습니다.
- 파란 반팔 셔츠·흰 칼라/소매 끝·가슴 배지·등 번호, 남색 반바지, 맨팔/종아리, 손목 밴드, 흰 양말·운동화/끈을 분리했습니다. 몸 전체를 단색으로 칠하지 않았습니다.
- 원래 얼굴/헤어 메시·UV·재질, 23관절 리그와 바인드 자세를 유지합니다. 기존 손·신발의 남긴 부분은 원래 스키닝을 유지하며, 새 의상은 같은 리그의 원본 표면에서 가중치를 전달합니다.
- 재생성: `blender -b --python tools/build-ranger-sports.py` (Blender 4.3+). 게임 실행에는 Blender가 필요 없습니다.
- `tests/ranger-outfit.test.ts`는 원본 파일 보존, 얼굴/헤어의 기하·UV·스킨 가중치 보존, 장비 제거와 의상 구분을 검증합니다. 익스포터의 정점 분할/미세한 소수 오차는 허용합니다.

검증: 77개 테스트, 빌드, 브라우저에서 오른손 패들·모델 표시·6스윙/높이별 접촉·이동·드라이브/딩크/발리·CPU·공 가림 표시. 한계: 의상은 가벼운 시험용 모델링으로 옷감 시뮬레이션이 없으며, 크게 꺾인 팔/높은 공에서는 소매와 팔이 겹치거나 늘어날 수 있습니다. 기존 얼굴의 콧수염/턱수염도 보존합니다.


## CPU Barbarian 시험 적용

현재 실제 경기의 CPU는 KayKit Barbarian 빨간 스포츠 버전입니다. 플레이어 Ranger, 크기(약 1.17m), 카메라와 경기 시스템은 유지합니다. 과거 단락에서 ‘기존 CPU’로 설명한 내용은 이전 시험 버전 기록입니다.

- 업로드 원본 `Barbarian.glb`와 원본 복사본 `public/models/Barbarian.glb`를 보존하고, 실행에는 별도 `public/models/Barbarian-sports.glb`를 사용합니다. 기존 `athlete.glb`도 삭제하지 않았습니다.
- 실제 리그는 Ranger와 같은 23관절 KayKit 리그이며 원본 바인드 행렬도 동일합니다. 원본 애니메이션 클립은 없습니다. 기존 KayKit 표시용 이동/6스윙/오른손 패들 IK를 재사용하며, Quaternius 관절 트랙을 강제로 적용하지 않습니다.
- 곰 모자와 일체형 모험가 의상/보호구를 제거하고, 빨간 셔츠·짙은 반바지·흰 양말·운동화를 같은 원본 리그에 스키닝했습니다. 얼굴·수염·SD 비율은 유지합니다. 오른손에는 CPU 색상의 피클볼 패들만 장착합니다.
- 재생성: `blender -b --python tools/build-ranger-sports.py -- --barbarian`. 옵션을 생략하면 기존 Ranger 제작 방식입니다. 이번 작업에서 기존 Ranger 모델 파일을 재생성하거나 변경하지 않았습니다.
- AI 반응/실수 확률/이동 속도/샷 선택·물리·충돌 범위·점수·규칙·알림은 변경하지 않았습니다. 모델 루트는 배율 1, 기존 CPU 위치/방향을 유지합니다.
- `animation-test.html`에서 선수를 CPU로 선택하면 Barbarian의 여섯 스윙을 확인할 수 있습니다.

검증: 80개 테스트와 빌드, 실제 경기의 모델/크기/패들·플레이어 이동·CPU 발리·드라이브/딩크/규칙, 두 캐릭터 6스윙·접촉 검사. 한계: 기존 KayKit 절차적 스윙의 큰 팔 뻗기와 의상 겹침은 남아 있으며, 원본 곰 모자를 제거해 민머리와 수염이 드러납니다.


## CPU 패들 가독성과 타격 이펙트

CPU 패들은 준비 자세에서 면이 옆으로 누워 얇게 보이고, 손/몸통 가까이에 겹쳤습니다. 오른손 장착 위치를 조금 바깥으로 옮기고, 준비 자세에서 몸 옆·앞에 면을 세워 보이도록 했습니다. CPU 패들만 15% 확대하고 밝은 면·짙은 테두리·양면 빨간 줄무늬로 구분합니다. 기존 타격 판정과 스윙 중 접촉 IK는 유지합니다.

- 드라이브: 하늘색 섬광과 두 줄의 작은 잔상, 0.16초
- 딩크: 연두색의 작고 부드러운 파동, 0.23초
- 발리(부드러운 발리 포함): 노란색 짧은 반짝임, 0.12초

`src/impact-effects.ts`는 재사용하는 네 개 슬롯만 사용하며 화면 흔들림이나 파티클 분사는 없습니다. 중심이 빈 반투명 효과를 랠리의 실제 타격이 확정된 공 좌표에 배치합니다. 플레이어와 CPU가 같은 시스템을 쓰며 헛스윙/반칙에는 효과를 내지 않습니다. 지속 시간은 게임 속도와 별개인 실제 초 기준이고, 일시정지 시 멈추며 움직임 줄이기를 반영하고 새 경기에서 초기화합니다.

기존 바운드 표시·공 윤곽선·모델 크기·카메라·AI·점수/규칙은 유지합니다. 검증: 84개 테스트, 빌드, 브라우저에서 양측 3가지 실제 타격의 효과 종류/발생 위치와 헛스윙/반칙 미발생, 6스윙 접촉 및 CPU 준비 패들 시야 확인.

## 야외 공원형 코트 배경

`src/park-environment.ts`가 시각 전용 공원 배경을 만듭니다. 기존 코트·키친·라인·네트, 13×23m 주변 바닥의 크기/높이, 캐릭터·카메라·공·타격·AI·규칙은 유지합니다.

- 차분한 잔디 바닥과 코트 주변 색상, 옆/뒤 산책로와 포장 이음선
- 양옆과 뒤쪽의 낮은 철망 펜스, 뒷문 입구. 앞쪽은 카메라 시야를 위해 열어 두었습니다.
- 펜스 바깥에 배치한 등받이/좌판 나무 벤치, 휴지통과 작은 음수대
- 여러 덩어리의 수관을 가진 공원 나무, 낮은 식재 상자, 낮 시간의 산책로 조명과 입구 표지
- 기존 햇빛/그림자/안개를 사용합니다. 추가 광원·움직이는 장식·노란 꽃/반짝임은 넣지 않아 공과 코트가 중심으로 보이도록 했습니다.

외부 모델/텍스처/API 없이 기본 도형과 공유 재질/기하를 사용하고, 펜스 기둥은 묶어서 렌더링합니다. 물체는 경기 이동 범위 바깥에 두며 배경에 충돌 판정을 추가하지 않습니다.

검증: 86개 테스트, 빌드, 넓은/좁은 브라우저 화면과 카메라 이동 양끝의 시야, 실제 이동·드라이브·딩크·발리·CPU 랠리/규칙 확인. `tests/park-environment.test.ts`는 장식의 이동 범위 침범, 기존 카메라에서 코트 가림, 배경 렌더링 규모를 검사합니다.
