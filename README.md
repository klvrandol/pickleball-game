# Pickleball Club

TypeScript + Three.js + Vite로 만드는 가벼운 3D 피클볼 게임입니다.
현재 **5단계: 사운드·애니메이션·조작감 개선**까지 구현되어 있습니다.

## Windows에서 실행하기

1. [Node.js 공식 사이트](https://nodejs.org/)에서 **LTS 버전(22.12 이상, 권장 24)**을 설치합니다.
2. 이 저장소를 다운로드하고 압축을 풉니다.
3. `package.json`이 있는 폴더를 열고, 탐색기 주소창에 `cmd`를 입력한 뒤 Enter를 누릅니다.
4. 처음 한 번 아래 명령을 입력합니다.

   ```bat
   npm ci
   ```

5. 실행할 때마다 아래 명령을 입력합니다.

   ```bat
   npm run dev
   ```

6. 명령 창에 표시되는 `Local` 주소를 Chrome 또는 Edge에서 엽니다. 보통 `http://localhost:5173`입니다.
7. 종료하려면 명령 창에서 `Ctrl+C`를 누릅니다.

`index.html` 파일을 직접 더블클릭하지 말고 위 방법으로 실행하세요. 패키지 설치에는 인터넷이 필요하지만 게임은 유료 서비스나 외부 API를 사용하지 않습니다.

## 현재 가능한 기능

- 실제 비율의 코트(20 × 44피트), 키친, 네트와 라인
- 파란 스포츠 셔츠의 플레이어와 빨간 스포츠 셔츠의 CPU
- 모델링된 얼굴·머리카락·목·손과 손가락, 자연스러운 인체 비율의 반팔·반바지·양말·운동화
- 선수별 복장·피부·머리카락 재질과 손목에 부착된 패들 면·그립
- 팔꿈치·무릎·발목 관절을 사용한 걷기와 몸통 회전·팔 스윙. 경기 판정은 캐릭터 루트 위치를 기준으로 기존대로 유지
- Quaternius의 CC0 리깅 인체 모델을 로컬 GLB로 불러옵니다. 두 선수는 메시를 공유하고 뼈대·복장 재질은 독립적으로 사용합니다.
- **W / A / S / D**: 앞 / 왼쪽 / 뒤 / 오른쪽으로 이동 (한글 입력 상태에서도 물리 키 기준)
- 대각선 이동 속도 보정, 빠르게 가속·감속하는 부드러운 이동
- 드라이브·딩크에 맞춘 팔 스윙과 몸 회전, 이동 시 기울임과 자연스러운 대기 동작
- 플레이어를 부드럽게 따라가는 3인칭 카메라
- 내 코트와 주변 여유 공간 안에서 이동, 네트 통과 제한
- 마우스 이동: 상대 코트의 노란 원으로 목표 지점 지정 (라인 밖도 조준 가능)
- **왼쪽 클릭**: 빠르고 낮은 드라이브 / **오른쪽 클릭**: 부드럽게 띄우는 딩크
- 딩크는 상대 키친 가까이에 직접 조준하세요. 네트 가까이에서 더 정확합니다.
- 공 가까이 접근하면 작은 이동 보조가 작동하지만 **자동 타격은 하지 않습니다.**
- 공이 너무 멀거나 너무 낮거나 높으면 헛스윙합니다. 화면의 초록색 타격 가능 안내를 참고하세요.
- 밝은 노란 공과 짙은 남색 윤곽선, 약 두 배 커진 기본 표시 크기와 원거리 가독성 보정
- 공 아래의 진한 그림자와 밝은 테두리, 대비를 강화한 예상 착지 원
- 오른쪽 위 **게임 속도**: **0.5배 / 0.75배(기본·권장) / 1배(기존 속도)**. 선택은 브라우저에 기억
- 속도 변경은 즉시 공·선수 이동·CPU 반응과 이동·타격 간격·경기 대기 시간에 함께 적용됩니다. 포물선과 경기 규칙은 유지됩니다.
- 중력, 감속 바운드, 네트 충돌, 아웃과 두 번 바운드 안내
- 보통 난이도 CPU: 공의 예상 바운드 이후 위치를 계산해 이동하고 타격
- 약 0.22~0.38초 반응 지연, 제한된 이동 속도와 타격 범위
- 네트 가까이에서 딩크, 후방에서 드라이브 선택. 가끔 빈 공간 공격
- 어려운 공은 헛스윙하거나 조준이 흔들리며, 타격 후 수비 위치로 복귀
- 점수판: **11점 이상 + 2점 차**로 승리. 서브권을 가진 선수만 득점
- 리시버가 랠리를 이기면 점수 없이 서브권 이동
- 서버 점수가 짝수면 오른쪽, 홀수면 왼쪽에서 대각선 서브
- 서브 착지는 키친·키친 라인을 제외한 올바른 서비스 코트에 해야 함
- **투바운스 룰**: 서브는 리시버 쪽에서, 첫 리턴은 서버 쪽에서 각각 바운드한 뒤 타격. 이후 발리 허용
- 키친 내부와 경계선에서 발리 금지. 키친 안에서 바운드한 공을 치는 것은 허용
- 발리 후 전진하며 키친에 들어가는 관성 반칙 검사, 득점 확정 전 판정 반영
- 사이드라인·베이스라인 착지는 인, 선 밖은 아웃. 두 번째 바운드는 리시버 폴트
- 네트·서브 발 위치·대각선 서비스 코트 폴트와 안내 메시지
- **랠리 횟수**: 서브부터 이어진 타격 횟수 (경기 점수와 다름)
- **새 경기** 버튼: 점수·서브권·두 선수 위치 초기화
- 득점·서브권 변경은 화면 중앙에 크게 약 2초간 표시하고 마지막 0.35초 동안 페이드아웃
- 플레이어 득점: `POINT! - 플레이어 득점` / CPU 득점: `CPU SCORES! - CPU 득점`
- 점수 없는 서브권 변경: `YOUR SERVE!` / `CPU SERVE!`
- 알림이 완전히 끝난 뒤 다음 서브를 준비. 속도 설정과 무관한 실제 시간 기준이며, 일시정지·탭 이동 중에는 알림 시간도 정지
- 경기 종료 시 `YOU WIN!` / `YOU LOSE!` 중앙 알림과 다시 경기하기. 상단 점수판은 계속 표시
- 드라이브·딩크·서브·바운드·네트·헛스윙·폴트·득점·서브권 변경·승패에 맞춘 효과음
- 오른쪽 위 **소리 켜짐/꺼짐**, **소리·화면 설정** 안의 음량 조절 (브라우저에 기억)
- **P / Esc** 또는 **일시정지** 버튼: 경기 멈춤/재개. 다른 창이나 탭으로 이동하면 자동 정지
- 예상 첫 바운드 위치 표시 (하늘색 원, 아웃 예상은 주황색), 타격 가능 거리 표시
- 좋은 타점·낮은 공·높은 공·먼 공 안내, 드라이브/딩크 타격 피드백
- 공의 짧은 궤적과 바운드·타격 파장, 득점 강조 효과
- **화면 효과 줄이기**: 궤적·파장·미세한 들썩임을 줄임. 운영체제의 모션 감소 설정을 기본으로 따르고 선택을 기억

## 처음 플레이하기

웹 배포가 완료되면 [게임 열기](https://klvrandol.github.io/pickleball-game/)를 누르세요.

1. 기본 속도는 **0.75배**입니다. 더 여유가 필요하면 오른쪽 위에서 **0.5배**, 이전 속도는 **1배**를 선택하세요. **경기 시작**을 누릅니다. 첫 서브는 플레이어입니다.
2. 처음 배치된 위치에서 **Space** 또는 **서브 공 떨어뜨리기**를 누릅니다.
3. 떨어진 공이 땅에 튀면 **왼쪽 클릭**으로 칩니다. 초록색 타격 가능 안내를 참고하세요.
4. 노란색으로 칠해진 대각선 서비스 코트를 마우스로 조준하세요. 마우스를 움직이지 않으면 기본 목표는 올바른 서비스 코트입니다.
5. 서브 후 W로 조금 전진해 다음 공을 준비하세요. CPU의 첫 리턴도 내 코트에서 바운드한 뒤 쳐야 합니다.
6. 이후 W/A/S/D로 이동하고 왼쪽 드라이브·오른쪽 딩크를 직접 클릭해 경기를 이어갑니다.
7. 공을 놓치면 점수·서브권 처리 후 다음 서브 위치로 두 선수를 자동 배치합니다. CPU 서브는 자동 진행됩니다.

소리는 **경기 시작 같은 직접 클릭 후** 재생됩니다. 오른쪽 위 버튼으로 언제든 음소거할 수 있고, 왼쪽 **소리·화면 설정**에서 크기를 바꿀 수 있습니다. 효과음은 브라우저에서 직접 합성하므로 외부 음원·다운로드·유료 서비스가 없습니다. 소리를 사용할 수 없는 환경에서도 게임은 동작합니다.

일시정지 후에는 **계속 플레이** 또는 P / Esc로 재개하세요. 창을 벗어나 자동 정지된 경우에도 직접 재개해야 합니다. 멈춘 동안 공과 CPU, 점수와 다음 서브 대기 시간이 모두 정지합니다.

하늘색 원은 현재 공의 속도와 중력으로 예측한 첫 바운드 위치입니다. 네트 접촉 이전의 예상이며 실제 착지·충돌 판정은 따로 이루어집니다. 초록색 타격 가능 표시와 함께 **좋은 타점** 안내를 참고하고, 낮은 공은 딩크를 사용해보세요.

서브 공을 놓쳤다면 Space로 다시 떨어뜨릴 수 있습니다. 서브 전에 선을 밟거나 다른 좌우 구역으로 이동하면 서브 발 반칙이 됩니다.

## 규칙 구현 범위와 단순화

공식 단식의 사이드아웃 점수 방식, 서브 좌우·대각선 착지, 투바운스 룰과 주요 키친 반칙을 구현했습니다. 이번 버전은 다음 부분을 단순화했습니다.

- **드롭 서브만 사용**합니다. 공을 밀어 던지지 않고 수직으로 떨어뜨려 바운드 후 타격합니다. 일반 발리 서브는 구현하지 않았습니다.
- 공의 착지 중심과 선 두께로 인/아웃을 계산하고, 선수 발은 작은 사각형 영역으로 판정합니다. 실제 공·발의 변형까지 계산하지는 않습니다.
- 발리 후 관성은 최소 **0.6초**, 그 이후에도 계속 네트 쪽으로 전진 중이면 멈추거나 뒤로 움직일 때까지 검사합니다. 이 기간의 키친 진입은 공이 이미 멈췄어도 폴트로 반영하며, 점수 확정을 잠시 미룹니다. 실제 신체 균형과 발걸음 전체를 재현한 판정은 아닙니다.
- 점프 버튼은 없습니다. 실제 조작 캐릭터는 지상에서 움직입니다. 규칙 엔진은 공중 상태가 전달되면 키친에서의 이륙과 착지를 추적하며, 키친에서 벗어나 양발이 다시 지면에 닿기 전 발리는 금지합니다.
- 네트 충돌은 즉시 폴트 처리합니다. 네트 테이프를 맞고 넘어가는 유효한 공과 서브는 재현하지 않습니다.
- 서브 10초 제한, 코트 엔드 교대, 타임아웃, 신체·복장·라켓의 우발적인 접촉 판정은 생략했습니다.
- 플레이어가 첫 서버로 고정됩니다. CPU도 4구부터 발리를 시도하며, 반응 지연과 실수 확률이 적용됩니다.


공은 시인성을 위해 표시만 크게 하고, 거리가 멀어지면 화면에서 너무 작아지지 않도록 보정합니다. 실제 충돌 반지름과 인/아웃 판정은 기존대로 유지합니다. 헛스윙 후에는 게임 시간 0.3초 뒤 다시 칠 수 있습니다(실제 시간은 0.75배에서 0.4초, 0.5배에서 0.6초). 불안정한 자세에서는 조준 오차가 생겨 네트나 아웃이 발생할 수 있습니다.

## 빌드 확인

```bat
npm test
npm run build
npm run preview
```

`build`는 TypeScript 오류 검사 후 배포 파일을 `dist` 폴더에 만듭니다. `preview`는 만든 결과를 확인하는 서버입니다.

## 파일 구성

- `src/main.ts`: 3D 코트와 캐릭터 연결, 이동, 카메라
- `src/athlete.ts`: 스키닝 인체 모델, 손목 패들, 원본 이동 애니메이션과 타격 IK
- `src/athlete-model.ts`: GLB 로딩·검증과 스켈레톤 복제
- `src/ball.ts`: 포물선 타격 계산, 중력·바운드·충돌
- `src/cpu.ts`: CPU의 예측 이동, 반응 지연, 타격 판단
- `src/match.ts`: 점수, 서브권, 서브 착지, 투바운스·키친 판정과 확정된 랠리 결과
- `src/result-notice.ts`: 결과별 중앙 문구, 실제 시간 2초 표시·페이드와 다음 서브 대기
- `src/audio.ts`: 외부 파일 없는 효과음 합성과 음량·음소거 설정
- `src/feedback.ts`: 예상 바운드와 타점 안내 계산
- `tests/`: 공·CPU·경기 규칙과 실제 서브 궤적 검사
- `src/style.css`: 안내 화면 디자인
- `index.html`: 화면과 조작 안내

## 개발 진행 상태

기본 기획의 1~5단계를 구현했습니다. 이후에는 실제 플레이 피드백에 맞춰 난이도와 타격감을 조정하고, 위에 명시한 규칙 단순화 항목을 개선할 수 있습니다.

## 발리 조작과 구현

- **서브(1구) → 바운드 후 리턴(2구) → 바운드 후 타격(3구) → 4구부터 발리** 순서입니다.
- 버튼은 그대로입니다. 왼쪽 클릭은 빠른 발리, 오른쪽 클릭은 부드러운 발리입니다. 마우스로 착지 지점을 조준합니다.
- 공이 공중에 있어도 패들이 닿는 범위와 높이에서만 타격됩니다. 클릭 후 약 0.065 게임 초의 스윙 준비를 거치며, 공이 그 사이 멀어지면 헛스윙합니다. 자동 타격은 없습니다.
- 실제 접촉 높이에서 궤적을 계산합니다. 빠른 공은 블록, 느리고 높은 공은 공격, 오른쪽 클릭은 짧고 부드러운 궤적을 사용합니다. 낮은 접촉은 네트에 걸릴 수 있습니다.
- CPU는 키친 밖에서 발리를 준비하고, 빠른 공에 블록·높은 공에 공격·네트 근처에 부드러운 발리를 사용합니다. 어려운 공은 놓칠 수 있습니다.
- `src/volley.ts`: 타격 범위, 스윙 접촉 시간과 발리 궤적
- `src/cpu.ts`, `src/main.ts`: CPU 판단과 기존 조작 연결
- `src/athlete.ts`: 접촉 높이에 맞춘 어깨·팔꿈치·패들 동작
- `src/match.ts`: 이륙·착지 상태와 키친 후속 반칙 판정
- `tests/volley.test.ts`: 투바운스, 발리·키친·CPU·점수 및 패들 접촉 검증

## 상황별 스윙 애니메이션

포핸드/백핸드는 선수의 몸 방향을 기준으로 공의 좌우 위치를 계산하여 선택합니다. CPU는 반대편을 바라보기 때문에 같은 월드 좌표의 공도 반대 손 방향으로 판정될 수 있습니다. 두 선수 모두 오른손 패들을 유지합니다.

- 드라이브: 큰 준비 회전과 빠른 임팩트, 몸을 가로지르는 높은 마무리
- 딩크: 작은 준비 동작과 부드럽게 밀어 올리는 짧은 마무리
- 발리: 짧은 준비와 빠른 블록, 작은 전방 마무리. 오른쪽 클릭의 부드러운 발리는 더 짧게 밀어냅니다.
- 백핸드: 몸 반대편에서 패들을 모으고 팔꿈치 방향 및 보조 팔 자세를 변경합니다.
- CPU는 동일한 시스템을 사용하며 회전과 마무리 크기를 약간 줄여 구분합니다. 공 접촉 위치와 시간은 동일합니다.

`src/swing.ts`가 타격 종류·손 방향·준비/임팩트/회복 시간을 관리하고, `src/athlete.ts`가 관절과 패들을 움직입니다. `src/main.ts`와 `src/cpu.ts`에서 실제 타격에 연결합니다. 애니메이션 때문에 공의 속도, 타격 판정, CPU 반응 지연이나 규칙을 바꾸지는 않습니다. 이제 로컬 GLB의 스키닝 모델·이동 애니메이션을 사용하며, 추가 패키지나 실행 중 외부 에셋 서비스는 사용하지 않습니다.

`tests/swing.test.ts`는 여섯 가지 조합의 실제 패들·몸통 자세 차이, 임팩트 오차, 선수 방향에 따른 손 선택, CPU 변형, 회복과 초기화를 확인합니다.

## 새 리깅 선수 모델

기존 구·막대 조합 캐릭터는 제거하고 **Quaternius — Smooth Male Casual (Animated Men Characters, February 2019)** 인체 메시로 교체했습니다. 얼굴·머리카락·목·손과 손가락, 반팔 셔츠·반바지·양말·운동화가 있는 스키닝 모델입니다. 인체를 Three.js 기본 도형으로 재생성하지 않습니다. 패들은 별도 장비로 만들어 오른손 손목 뼈에 부착합니다.

- `assets/athlete.glb`: 약 837 KiB. 스키닝 메시·31개 관절·대기/걷기/달리기 클립이 포함된 단일 파일. 이미지나 별도 바이너리 요청이 없습니다.
- 어깨·팔꿈치·손목·허리·고관절·무릎·발목과 손가락을 사용합니다. 파란 선수와 빨간 선수는 독립된 스켈레톤을 가집니다.
- 원본 이동 클립을 혼합하고 뒤로 이동할 때 역재생하며, 좌우 이동에는 사이드스텝 보정을 추가합니다. 포핸드/백핸드 및 드라이브/딩크/발리는 기존 타격 시계에 맞춰 뼈대 위에 적용합니다.
- 낮은 공에서는 몸을 낮추고 다리 관절을 보정합니다. 애니메이션은 시각 표현만 변경하며, 이동 좌표와 공 물리·타격 범위·AI·점수·규칙은 유지합니다.
- 처음에는 “선수 모델 불러오는 중…”을 표시합니다. 로딩 실패 시 오류를 알리고 시작을 막습니다. 이전 도형 캐릭터로 대체하지 않습니다.
- 모델은 배포 파일에 포함되므로 **사용자가 추가로 다운로드하거나 계정을 만들 필요가 없습니다.** 실행 방법은 기존 `npm install` → `npm run dev`와 동일합니다.

출처·정확한 라이선스와 다시 확보하는 방법은 [models-src/README.md](models-src/README.md)를 확인하세요. 현재 저장된 원본에는 **CC0 1.0 Universal**이 적용되어 있습니다. 원본도 저장했으므로 Blender 4.3 이상이 설치된 개발 환경에서는 다음 명령으로 GLB를 다시 만들 수 있습니다. 일반적인 게임 실행에는 Blender가 필요하지 않습니다.

```bash
blender -b models-src/Quaternius_Smooth_Male_Casual.blend --python tools/export-athlete.py
npm run build
```
